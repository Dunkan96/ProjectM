ПОЛНЫЙ ПРОМПТ ПРОЕКТА «МОНИКА» (v4.0)
Назначение: Этот документ содержит полное описание проекта для передачи контекста в новый чат или другую нейросеть. Прочитай его целиком перед тем как предлагать изменения.

1. СУТЬ ПРОЕКТА
Моника — AI-VTuber с живым поведением, многослойной памятью, голосом и Live2D-аватаром. Бэкенд написан на Python, аватар отображается в браузере через PIXI.js + Live2D Cubism 4. Управляется текстом с клавиатуры или голосом (Push-to-Talk, клавиша F10). Есть Telegram-бот как второй интерфейс. LLM — локальная модель Qwen3-14B через LM Studio.

Ключевая особенность: Моника — не просто чат-бот. У неё есть граф знаний (SQLite), векторная память диалогов (ChromaDB), социальные отношения с пользователями (доверие, раздражение, модерация), память желаний и мнений, эмоциональная память событий, межсессионная непрерывность диалогов. Всё это собирается в системный промпт для LLM и влияет на тон, длину и содержание ответов.

4. АРХИТЕКТУРА СВЯЗИ
Поток обработки сообщения:
Пользователь вводит текст (или F10 → STT)

Создаётся Stimulus → priority_queue

generate_response() → process_input():

Проверка на запрещённый контент

Обновление social_layer (отношения)

Проверка специальных запросов (identity, lyrics, experience, repair)

Поиск в памяти (граф + ChromaDB)

LiveEngine.before_plan (ритм, интерес, скука)

BehaviorDirector.plan_response (режим, длина, тон)

Сборка system_prompt (Persona + режим + желания + мнения + отношения + live_context)

LLM-генерация (Qwen3-14B)

Постпроцессинг (очистка от RP, удаление выдуманных воспоминаний, защита от повторов)

TTS (Silero) + отправка эмоций и липсинга на аватар

WebSocket для аватара (ПОРТ 8080):
Python-сервер в отдельном потоке (start_avatar_ws)

_ws_queue (queue.Queue) для потокобезопасной отправки

_ws_sender() читает очередь и отправляет JSON

send_avatar_emotion(emotion, intensity)

send_avatar_mouth(value) — липсинг

viewer.html подключается по ws://localhost:8080

Липсинг:
_send_lipsync() — поток, параллельный sd.play()

Чанки по 50 мс, RMS громкости → mouth = min(1.0, rms * 5)

_lip_stop флаг для прерывания старого липсинга новым

После аудио: lip_thread.join(timeout=2.0), принудительное закрытие рта, очистка очереди

Этот хак переименовывает ID параметров на несуществующие, чтобы Cubism Core не мог ими управлять. При обновлении pixi-live2d-display может сломаться.

Автономные движения (setInterval 50ms):
Голова: ParamAngleX (±7.5°), ParamAngleY (±5°), ParamAngleZ (±6°)

Глаза: ParamEyeBallX/Y (синусоида ±0.1)

Тело: ParamBodyAngleX/Y (малая амплитуда)

Дыхание: ParamBreath (синусоида 0.5 ± 0.15)

Цели обновляются каждые 3-6 секунд, плавное сглаживание 0.03

Эмоции (по WebSocket setEmotion):
6 эмоций: Happy, Sad, Angry, Surprised, Embarrassed, Suspicious
Каждая задаёт комбинацию параметров рта, бровей, глаз, щёк.

Липсинг (по WebSocket setMouth):
ParamMouthOpenY = value * 2

Авто-моргание:
Каждые 3-5 секунд, закрытие на 80 мс.

6. ПАМЯТЬ

facts (subject_id, predicate, object_id, importance, last_accessed, access_count)

Рейтинг = importance * time_decay * freq_bonus

HALF_LIFE_DAYS = 7

Факты добавляются автоматически и вручную ("запомни факт")

Оперативная память (knowledge.db):
chat_history, stream_events, topic_weights, user_reputation

relationship_state, monika_desires, monika_opinions

emotional_events, dialogue_sessions

ChromaDB (chroma_engram/):
Коллекция dialogue_memory для векторного поиска по диалогам

LiveEngine:
MoodSystem: настроение-фон (playful, soft, careful, neutral)

8. LLM ИНТЕГРАЦИЯ
LM Studio, порт 1234, OpenAI-совместимый API

Модель: Qwen3-14B (GGUF, квантованная)

ОСОБЕННОСТЬ: требует /no_think в промпте чтобы не генерировать <think>-рассуждения

Temperature динамическая (0.55-0.85)

max_tokens: 84-345 в зависимости от плана ответа

Penalties динамические через behavior_director.adjust_sampling

9. ИЗВЕСТНЫЕ ПРОБЛЕМЫ
АВАВА в конце речи — губы могут дёрнуться после окончания TTS. Не исправлено до конца.

Дублирование get_relevant_desires в desire_memory.py (метод определён дважды).

Иногда повторяет ответы — защита от looping есть, но не всегда срабатывает.

WebSocket-сервер хрупкий — правильная последовательность: run_until_complete → run_forever.

Авто-слежение за мышкой может вернуться при обновлении pixi-live2d-display.

Engram отключён — используется только граф знаний.

Папка Logs/ не добавлена.
